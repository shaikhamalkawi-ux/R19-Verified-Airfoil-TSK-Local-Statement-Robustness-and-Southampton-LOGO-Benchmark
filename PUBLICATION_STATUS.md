## Administrative actions before a formal software release

Confirm the author/maintainer names, select a code license consistent with third-party source terms, approve public repository metadata and the immutable code/data archive, and then consider tagging a stable commit and publishing a GitHub Release. **Zenodo follows acceptance**, subject to the actual publisher and author permissions. A documentation correction may be committed without changing the locked experimental archive; changing numerical evidence requires an explicit scientific revision and new audit.
